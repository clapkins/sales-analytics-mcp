# Скриншоты работы системы

Диалог с Claude Desktop, подключённым к MCP-серверу `sales-analytics`.
Снято на реальном прогоне: пользователь отправляет одно сообщение с
путём к файлу, дальше модель ведёт цепочку вызовов сама.

| Файл | Что на нём |
|---|---|
| `01_dialog_load_and_clean.png` | Запрос пользователя, вызов `load_data`, лог очистки: 27 нормализованных значений `Region`, 5 дублей, по 12 пропусков |
| `02_report_saved_and_data_quality.png` | Отчёт сохранён через `export_report`; вывод про 4 реальных региона, превратившихся в 15 |
| `03_margin_by_product.png` | Таблица маржи по товарам — модель посчитала её сама из двух рейтингов |
| `04_findings_correlation_regions.png` | Находка про Wireless Mouse, корреляция `Quantity`↔`Profit`, разбор регионов |
| `05_recommendations.png` | Практические рекомендации с приоритетами |
| `06_analysis_caveats.png` | Оговорки об ограничениях данных, которые модель сформулировала сама |
| `07_generated_charts.png` | Содержимое `charts/` после прогона |

Полный текст отчёта из этого прогона —
[`reports/sample_report.md`](../../reports/sample_report.md).

## Что видно на скриншотах, кроме успешного сценария

На `01` и `06` модель сообщает, что вызов `clean_data` завис и не
вернул результат, и она взяла готовый `ds_1_clean`, уже лежавший в
session store от предыдущего диалога.

Это оставлено намеренно, а не выбрано как удачный кадр. Разбор
причины и исправление — в
[ARCHITECTURE.md](../../ARCHITECTURE.md), раздел «Проектирование под
то, как модель воспринимает результат».
