ТЕСТОВОЕ ЗАДАНИЕ: Аналитическая система на базе LLM с интеграцией MCP (работа через веб-интерфейсы готовых чатов)

ОБЩЕЕ ОПИСАНИЕ
Вам предстоит разработать прототип аналитической системы, которая позволяет пользователю загружать структурированные данные (файлы CSV/Excel) и получать автоматизированный отчёт с графиками и выводами. Система использует уже существующую LLM-платформу (например, ChatGPT, DeepSeek, Qwen, Kimi и т.п.) – вы можете взаимодействовать с ней как через веб-интерфейс (с поддержкой внешних инструментов), так и через официальное API (на ваш выбор).
Ключевое требование: вы не разрабатываете собственный чат-интерфейс с нуля. Вместо этого вы создаёте набор скиллов (навыков) и MCP-сервер (или аналогичную систему инструментов), которые подключаются к выбранной LLM-платформе и позволяют ей выполнять аналитические операции – загрузку данных, очистку, построение графиков, генерацию отчётов. Регуляризация процесса достигается за счёт продуманной архитектуры скиллов и цепочки вызовов, управляемой LLM.

ЦЕЛЬ ЗАДАНИЯ
Проверить ваши навыки в следующих областях:
практическое использование современных LLM-платформ (через веб-интерфейс или API) для решения прикладных задач;
проектирование расширяемой архитектуры скиллов и инструментов;
интеграция внешних сервисов через MCP (Model Context Protocol) или аналоги;
работа с данными и визуализация. 

ОПИСАНИЕ ЗАДАЧИ
1. Выберите LLM-платформу и способ взаимодействия
Вы можете использовать любую из популярных платформ:
ChatGPT (с поддержкой Custom GPTs и Actions – вызов внешних API);
DeepSeek (с поддержкой MCP-серверов или функций);
Qwen (с плагинами или функцией вызова инструментов);
Kimi (Moonshot) с аналогичными возможностями;
или любую другую, которая предоставляет механизм вызова внешних инструментов (tool calling, actions, plugins).
Варианты реализации:
Через веб-интерфейс: вы настраиваете внешний инструмент (например, Action в ChatGPT) так, чтобы LLM могла вызывать ваш MCP-сервер. В этом случае вы реализуете только серверную часть и описываете спецификацию инструментов (OpenAPI, схема MCP).
Через API: вы пишете скрипт, который отправляет запросы к API модели, используя встроенный механизм function calling.
Выберите тот способ, который вам удобнее. Главное – показать, что LLM может управлять вашими скиллами и инструментами.
2. Реализуйте базовый сценарий работы
Пользователь (через чат-интерфейс выбранной платформы) загружает файл с данными (например, sales_data.csv с колонками: Date, Product, Region, Sales, Quantity, Profit) и даёт запрос на анализ, например: «Проанализируй продажи, построй графики и дай рекомендации».
Система (ваш MCP-сервер + скиллы) должна:
автоматически определить структуру данных;
выполнить предварительную очистку (обработка пропусков, выбросов);
построить не менее трёх информативных графиков (например, динамика продаж, распределение по продуктам/регионам, корреляционная матрица);
сформулировать ключевые выводы и практические рекомендации на основе данных, используя LLM для генерации связного текстового отчёта.
3. Интегрируйте внешние инструменты через MCP
Реализуйте MCP-сервер (или его упрощённый аналог), который предоставляет следующие инструменты (они должны быть доступны для вызова из LLM через механизм tool calling / actions):
load_data(file_path) – загрузка данных;
describe_data(df) – базовая статистика;
plot_trend(df, x_col, y_col) – построение графика тренда;
plot_distribution(df, col) – гистограмма распределения;
correlation_analysis(df) – матрица корреляций (тепловая карта);
(опционально) другие полезные инструменты.
LLM должна уметь выбирать и вызывать эти инструменты в процессе анализа, передавая им необходимые аргументы. Вы можете использовать официальную библиотеку mcp от Anthropic или написать собственную реализацию на базе FastAPI / Flask. Если вы работаете через веб-интерфейс, опишите спецификацию инструментов в формате OpenAPI и настройте интеграцию с платформой (например, через Custom GPT Action).
4. Создайте «скиллы» для регуляризации процесса
Скиллы – это абстракции, которые группируют логику выполнения типовых этапов анализа. Реализуйте их как отдельные классы/функции на серверной стороне. Примеры скиллов:
DataLoadingSkill – загружает данные, выводит информацию о структуре, количестве записей и пропусках;
DataCleaningSkill – выполняет очистку (заполнение пропусков, удаление дубликатов, нормализация);
VisualizationSkill – строит графики на основе заданных параметров;
InsightGenerationSkill – принимает результаты анализа и генерирует текстовый отчёт с выводами.
Продемонстрируйте, как LLM использует эти скиллы в цепочке рассуждений. Для этого вы можете:
описать в системном промпте (или инструкции для Custom GPT) последовательность шагов;
или реализовать логику, которая позволяет LLM вызывать скиллы в нужном порядке через инструменты.
5. Обеспечьте расширяемость
Предусмотрите возможность лёгкого добавления новых скиллов или инструментов без изменения ядра системы (например, через регистрацию в фабрике, плагинную архитектуру или конфигурацию).
