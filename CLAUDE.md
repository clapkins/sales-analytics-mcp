# CLAUDE.md — контекст проекта

Этот файл читается в начале каждой сессии. Правила ниже обязательны и не пересматриваются без явного указания пользователя.

## Что это за проект

Прототип аналитической системы: MCP-сервер + набор скиллов, через которые LLM анализирует загруженные табличные данные (CSV/Excel), чистит их, строит графики и генерирует текстовый отчёт с выводами.

Это тестовое задание для трудоустройства. Оценивается не только работоспособность, но и архитектура, чистота кода, документация. Проверяющий — человек, который будет читать репозиторий, а не только запускать его.

**Рекомендуемый объём по ТЗ — 4–6 часов работы.** Не раздувай scope: качество исполнения заявленного объёма важнее количества фич.

## Стек

- Python 3.11+
- `fastmcp` — MCP-сервер (транспорты stdio и streamable-http)
- `pandas` — работа с данными
- `matplotlib` + `seaborn` — графики (никакого plotly, нужны статичные PNG)
- `openpyxl` — чтение Excel
- `ruff` — линтер и форматтер
- `pytest` — тесты

Зависимости фиксируются в `pyproject.toml`. Виртуальное окружение — `.venv`.

## Архитектурные инварианты

Это жёсткие правила. Нарушение любого из них — ошибка, а не компромисс.

1. **DataFrame никогда не пересекает границу LLM.** `load_data` кладёт датафрейм в session store и возвращает `dataset_id` + компактную сводку. Все остальные инструменты принимают `dataset_id: str`, а не сам датафрейм. В ТЗ фигурирует сигнатура `describe_data(df)` — мы сознательно от неё отходим, обоснование идёт в ARCHITECTURE.md.

2. **Инструменты MCP — тонкие обёртки над скиллами.** Вся бизнес-логика живёт в скиллах. В слое инструментов допустима только валидация аргументов и сериализация результата.

3. **Список инструментов генерируется из реестра скиллов.** Руками инструменты не перечисляются. Добавление скилла не должно требовать правок в `core/`.

4. **Ошибки пишутся для LLM, а не для человека.** Никаких голых исключений наружу. Вместо `KeyError: 'Sale'` инструмент возвращает структурированный ответ: что пошло не так, какие значения допустимы, и — если применимо — предложение ближайшего совпадения. Модель должна уметь исправиться на следующем шаге без участия пользователя.

5. **Графики возвращаются как путь к PNG плюс текстовое описание того, что на графике.** Модель картинку не видит. Без описания она не сможет корректно сослаться на график в отчёте.

6. **Выводы и рекомендации генерирует LLM, а не код.** `InsightGenerationSkill` собирает и структурирует факты (статистика, лог очистки, описания графиков). Никаких захардкоженных формулировок вида «продажи выросли на X%».

## Соглашения

- **Язык:** докстринги, комментарии, README и весь текст, который увидит проверяющий, — на русском. Имена переменных, функций и классов — на английском.
- **Докстринги:** у каждого публичного класса, метода и функции. Формат Google-style.
- **Типизация:** аннотации типов везде в публичных сигнатурах.
- **PEP 8:** `ruff check` и `ruff format` должны проходить чисто. Это прямой пункт критериев оценки.
- **Коммиты:** по одному на этап плана, осмысленное сообщение на русском. История коммитов — единственное объективное свидетельство того, как шла работа, поэтому она должна читаться как последовательность разумных шагов.

## Чего делать НЕ надо

- Docker, CI/CD, аутентификацию HTTP-транспорта, стриминг больших файлов, базу данных. Всё это упоминается в ARCHITECTURE.md в разделе «что доделал бы дальше», но не реализуется.
- Собственный чат-интерфейс. По ТЗ это прямо запрещено — используется готовый клиент.
- Абстракции «на будущее», у которых сейчас одна реализация.

## Визуальная приёмка графиков

Проверка «код отработал без исключений» ничего не говорит о том, как график выглядит. Matplotlib молча выпускает нечитаемые изображения.

**Обязательный шаг после генерации любого графика: открой получившийся PNG инструментом чтения файлов и посмотри на него.** Ты умеешь читать изображения — пользуйся этим. Проверь по списку:

- Подписи оси X не наезжают друг на друга (частая беда с датами — нужен поворот или прореживание тиков).
- Длинные названия категорий не обрезаны краем изображения.
- Легенда не перекрывает данные и не вылезает за границы.
- Заголовок не сливается с верхним рядом данных.
- В тепловой карте видны и подписи, и значения в ячейках.
- Числа на осях читаемы — не `1e6` без пояснения, не наложение делений.
- Ничего не выходит за пределы холста (`bbox_inches="tight"` при сохранении).
- При большом числе категорий столбчатая диаграмма не превращается в частокол — либо горизонтальная ориентация, либо топ-N.

Если что-то из этого нарушено — чини и перечитывай PNG заново, пока не станет чисто. Не показывай пользователю графики, которые сам не посмотрел.

Проверяй каждый график на реальных тестовых данных, а не на трёх синтетических точках: проблемы наложения проявляются именно на полном датасете.

## Чистота кода: что считается мусором

Перед каждым коммитом прогоняй проверку. Мусором считается:

- Неиспользуемые импорты, переменные, аргументы, функции и целые модули.
- Закомментированный код. Любой. История есть в git.
- Отладочные `print`, оставленные логи уровня debug.
- `TODO` и `FIXME` без пояснения, кто и когда это сделает — либо доделай, либо перенеси формулировкой в раздел «что доделал бы дальше» в ARCHITECTURE.md.
- Функции, которые нигде не вызываются.
- Файлы, на которые никто не ссылается: черновики, `test.py` в корне, `output_old.png`, дубли конфигов.
- Дублирующая логика: две функции, делающие почти одно и то же. Если заметил — сведи в одну, не оставляй обе.
- Пересечение ответственности между скиллами: если очистка данных начала происходить и в `DataLoadingSkill`, и в `DataCleaningSkill` — это ошибка проектирования, а не мелочь. Разграничивай явно.
- Пустые классы, обёртки без поведения, абстракции с единственной реализацией и без второго кандидата.
- Артефакты прогонов в git: временные PNG, `.ipynb_checkpoints`, кэши. Всё, кроме итоговых графиков в `charts/`, попадает в `.gitignore`.

Конкретные команды: `ruff check --select F401,F841,ARG,ERA001,RUF100`, затем `ruff format --check`. Дополнительно пройди `git status` и глазами по списку файлов — всё ли из этого должно быть в репозитории.
